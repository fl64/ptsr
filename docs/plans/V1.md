# Plan: the minimum for v1.0.0

Read this plan before the other plans. It defines the owner's release scope, not current capabilities.
It takes priority over the broader plans and the historical stages in `../VISION.md`.
The vision and plans are guides. Requirements come from `openspec/specs/` and the active change.
Before each implementation change, write its OpenSpec proposal, design, spec deltas and tasks.
Activate one change at a time. This document activates none.

## 1. The core of 1.0

One complete, polished loop:

> sample → chop → pads → pattern → resample → effects → export,
> from the keyboard and the SMC-PAD, with no clicks and no crashes.

A change belongs to 1.0 only if this loop needs it, or a release criterion requires it.
Every other idea is `1.x` in [the backlog](../BACKLOG.md).
Only the owner can move an item into 1.0. The agent cannot expand the scope.
The owner added the glitch kit and serial effect chains to 1.0 on 2026-11-07.
The main sound is glitch ambient: chopped beats, digital debris and stretched textures.
The release also supports fast breaks and hard, distorted styles. A clean breakbeat alone does not meet this scope.

Use the keyboard and controller paths in each change's design.
Keep commands outside the pad block. Shift on a pad remains full hit velocity.
Use `VISUAL.md` for modes, pad states, values, errors and hints for both inputs.
Test shared actions with keyboard events and raw MIDI through production profiles and dispatch.
No allocation, locks, I/O, logging or panics in the audio callback.

## 2. Release criteria

All eight criteria must pass. No criterion is complete because this plan exists.

1. **Three finished tracks.** The owner makes one track in each of these styles:
   - Glitch ambient with chopped beats and stretched textures, the main sound of the project.
   - A fast break-based style: drum and bass or jungle.
   - A hard, distorted style: industrial hardcore or hard techno.

   Each starts in an empty project and ends in an exported WAV, using only ptsr.
   Each session adds its date, slow or impossible tasks and wanted tools to [V1-FRICTION.md](../V1-FRICTION.md).
   Each log item names its source track. All core items must close before release. Non-core ideas remain `1.x`.
2. **No clicks.** The owner checks the sound during normal use and listens to each sound change's renders.
   Investigate a reported click from its reproducible scenario before choosing a correction.
   Distinguish unwanted clicks from sharp transients already in the source audio.
3. **Callback budget.** With 32 voices, a full pattern and both shared sends, the callback meets the 50 % target.
   Include a full insert chain on every sounding pad and the full master path.
   Include simultaneous ratchets on 16 pads at a 1/32 rate and 200 BPM.
   Test buffers of 128 and 256 frames. State the sample rate and full active effect path.
   Resolve the open slow-core issue, or explain it with a measured operating limit for owner review.
   Record maxima and exceedance counts, not only p99 or command success.
   A measured limit does not silently relax the 50 % target or close the existing gate.
4. **Soak test.** Run a pattern with effects and random virtual MIDI and keyboard input for four hours.
   At buffer 256: no xrun, no crash and no memory growth above a set limit.
   Define the memory limit, workload, measurement method and audio test setup before code.
   Add `task soak`. This command does not exist as a result of this plan.
5. **Both inputs.** The reach test from 93 passes.
   The owner completes at least one full track with the SMC-PAD and the keyboard out of reach.
   Typed names are the exception.
6. **Owner checks.** For every 1.0 change, the owner completes keyboard, controller and listening checks in [LIVE-CHECKS.md](../LIVE-CHECKS.md).
   Acceptance without checks does not pass this criterion. Earlier acceptance does not close missing checks.
7. **Project format promise.** A project saved by 1.0 opens in every 1.x release.
   Keep fixtures for each format version in the repository and load them in tests.
   Later migrations preserve the project sound. Protection against damaged or newer files remains.
8. **Install.** A clean machine runs ptsr from the release binary.
   `ptsr doctor` reports the audio backend, system audio libraries, real-time priority, MIDI, terminal and kitty protocol in plain words.
   This is a planned command, not a current install instruction.

### Milestone 0.4b — glitch kit

Goal: make chopped, unstable rhythms and stretched textures, not only clean breakbeats.
Implement these changes in the listed order. Each uses the pattern model from 96.
The names below reserve scope, not active changes or final controls.

**Held performance rule:** this applies to held uses of `step-ratchet`, `stutter` and `roll-matrix` over a running pattern.
The pattern clock keeps running underneath. Its normal output is silent while the effect supplies the sound.
Start the effect on the next 1/16 boundary, not at the press. A setting selects 1/16 or 1/32, with 1/16 as the default.
Keep normal pattern output audible until that start.

On release, return to the sound from the next pattern hit, without an unintended gap or a doubled hit.
Keep written step ratchets distinct from this held performance path.
Add a separate timing render for each case: press between steps, release between steps, and press/release within one step.

- **`step-locks`:** each hit can store its own slice, start point, reverse, pitch and filter cutoff.
  In step mode, hold a step and turn a knob. Choose the keyboard path in the design.
  This moves the minimum part of 104 into 1.0. More lockable parameters remain in 104 for `1.x`.
- **`step-ratchet`:** repeat a hit 2–8 times inside its step.
  Add a pitch ramp of −12 … +12 semitones over those repeats and a velocity ramp up or down.
  Each hit has a probability from 0–100 %, in steps of 5 %.
  A held performance use follows the rule above. Stored ratchets remain part of the written pattern.
- **`stutter`:** while held, capture a short part of the master sound and repeat it in tempo.
  A knob selects 1/4, 1/8, 1/16, 1/32 or 1/64.
  Provide keyboard and controller hold paths, with click-free capture and release.
  Follow the held performance rule: quantized start, the pattern running underneath with its normal output silent, and return on the next hit.
  Never add an unintended gap or a doubled hit at release.
  No latch fallback is necessary for stutter in 1.0. Stutter on individual pad chains remains `1.x`.
- **`roll-matrix`:** a 4×4 matrix of held roll effects on the current pattern sound.
  Choose the target in the design: master, selected pad, or the pattern's last hit. The default is the last hit.
  Follow the held performance rule above.

  | Row (rate) | Column 1 | Column 2 | Column 3 | Column 4 |
  |---|---|---|---|---|
  | 1/4 | repeat | build | stretch all | echo |
  | 1/8 | repeat | down | up | shrink |
  | 1/16 | repeat | down | up | shrink |
  | 1/32 | repeat | down | up | shrink |

  - **Repeat:** repeat the hit at the row rate.
  - **Down / up:** each repeat is one whole tone lower / higher than the previous repeat.
  - **Shrink:** each repeat is shorter and quieter.
  - **Build:** play at 1/4, then 1/8, then 1/16, then 1/32, for one beat each.
  - **Stretch all:** play every pattern hit stretched with the real-time old-sampler stretch from section 4, when available.
    Until then, play at half speed, one octave down. The 1.x stretch does not block this 1.0 cell.
  - **Echo:** use dotted 1/8 repeats. Each repeat is quieter and darker.
  - **SMC-PAD:** a panel cell turns the latched `ROLL` layer on or off. Hold the 16 pads to play matrix cells.
  - **Keyboard:** a right-half key turns `ROLL` on or off. The 16 pad keys then play held matrix cells.
    Choose the command key in the design. With no key-release events, a cell plays for one bar.
    This fallback belongs to the matrix, not to stutter.
  - **Visible state:** show the `ROLL` badge. Pad glyphs show the rate and variant, under the rules in [VISUAL.md](VISUAL.md).
  - **Renders:** render each of the 16 cells at 172 BPM. Check level, timing and clicks automatically.
- **`stretch-offline`:** stretch a pad or slice into a new sample with the PaulStretch method.
  Use overlapping FFT windows with random phases. The stretch factor is 2 … 50, with a window-size setting.
  Process outside the audio thread. Show progress and put the resulting new sample on a pad.
  An original implementation can follow the method. Check source licenses before reuse and run `cargo deny` for any library.

Tests: saved per-hit locks, pad-value restoration, ratchet count and ramps, probability boundaries and exact timing.
Test keyboard and raw MIDI routes, stutter capture/release, background progress, cancellation and safe result placement.
Repeat the callback gate with 1/32 ratchets at 200 BPM on 16 simultaneous pads.
Renders check finite samples, clipping, intentional silence, level, timing and clicks.
For held effects, render all three press/release cases above and check the audible handover against the running pattern.

**Open design cases:** this plan records normal timing and the no-release fallback. Resolve these cases before their implementation specs:

- **Open:** a press and release both arrive before the queued start. Define whether to cancel or play a minimum roll.
- **Open:** the owner holds two cells, or keyboard and MIDI holds overlap. Define priority and which release ends the effect.
- **Open:** the pattern advances between press and effect start. Decide when to capture the last-hit source.
- **Open:** the pattern stops or changes, `ROLL` closes, or a controller disconnects during a hold.
  Define cleanup and the source of the next audible hit. No old hold may survive into an unrelated pattern.

The owner makes a glitch pattern with each input and listens to each change's render.
Name those render files in the implementation proposals. This plan creates none.

### Milestone 0.5 — tempo, resample, effects and export

Goal: complete the sample-to-export loop.

- **102, reduced scope:** `bpm` / `beats` per sample, length in N bars, tempo-grid chopping and pad fit by repitch.
  Tempo detection is a proposal for owner confirmation, with ×2 / ÷2 correction.
  Tempo-following stretch is outside 102. The separate extreme offline stretch is in 0.4b.
- **105:** resample a pad, pattern or ptsr master for N bars, from bar line to bar line, onto a new pad.
  Print effects into the result. Keep unrelated device-monitor audio outside these internal sources.
- **`113-fx-core`:** use two kinds of effect places. Decide this architecture before adding more effects.
  Build its insert chain on the per-pad bus from [FX-FILTERS.md](FX-FILTERS.md).
  That plan handles drive and delay tempo sync first. Do not repeat them in 113.
  - **Sends, existing:** shared reverb and delay. `delay-v2` in the FX and filters plan adds tempo divisions before 113.
  - **Inserts, new:** a serial chain of up to four effects on each pad and on the master.
    The owner can change the effect order.
    The 1.0 insert effects are drive / waveshaper, bit and rate crusher, filter and compressor.
    Keep the per-voice pad filter outside the insert chain, as specified in `filter-v2`.
    The compressor has threshold, ratio, attack, release and makeup.
  - **Master:** put a clipper before the always-on limiter from 111.
    Offer soft and hard clipping with a drive amount. The clipper defaults to off. The limiter stays on.
  - **Level matching:** more effect amount changes the character, not the loudness.
    Give each fx-core effect a makeup gain curve.
    A reference render checks RMS at 0 %, 50 % and 100 % amount, within ±1.5 dB of the reference level.
    Define the reference sound, measurement window and limit in the design. Intentional roll decays are not fx-core amount changes.
  - **DJ filter:** one master knob gives low-pass on the left, off at the centre and high-pass on the right.
    Add a small resonance rise while the knob moves. Return to flat resonance at rest.
    Smooth the transitions, with no click at the centre.
  - **Lo-fi:** one insert knob reduces sample rate and bit depth together.
    The rate goes from the project rate down to 6 kHz. The depth goes from full resolution down to 6 bits.
  - **Real time:** no allocation in the callback. Replace a prepared chain with an `Arc` swap.
    Retire old chains outside the callback. Each effect needs renders with automatic checks.
    Criterion 3 includes a full chain on every sounding pad and the complete master path.
  - **Later buses:** groups of pads with their own chains are `1.x`. Leave room for them in the design.

  Distortion, clipping, crushing and filter chains process the pad or master signal in series, not as shared sends.
- **`114-sample-ops`:** trim silence, fade in/out, reverse and remove DC, one key or panel cell each.
  Keep threshold and fade-length settings. Operations stay non-destructive until bake.
  Pad loop playback belongs to the separate `pad-loop` item below.
- **`pad-pitch-env`:** a pitch envelope on each pad, with start offset −48 … +48 semitones and a decay time.
  One knob pair on a pad edit page controls it. Use it for punchy kicks and pitch drops.
- **`pad-loop`:** loop pad playback with a crossfade at the loop point and a crossfade-length setting.
  A gate pad loops while held. A one-shot pad loops until the next hit of that same pad.
  Slice playback follows the per-pad pitch gate from 96, on by default for slices.
  Chop assignment keeps existing mute groups, with off on fresh pads.
- **`115-export`:** render a slot or a list of slots, each for N repeats, to a WAV file offline.
  Reuse the offline engine. Offer 24-bit or 32-bit float at the project sample rate.
  Keep live output recording (`Ctrl+T`) for performances. Do not silently treat it as isolated offline export.

Not in 1.0: break to pattern (103), extra locks from 104 and bass play (106).
Sidechain and LUFS (107), LFOs (108) and stems also remain `1.x`.
The minimum locks are in 0.4b. The delay divisions and compressor do not activate the full scope of 107–108.

Tests cover sample tempo and correction, repitch ratio, exact N-bar resample length, latency compensation and isolated sources.
Also test effect tails, insert order, chain swaps, clipper/limiter order and exported file format/rate/length.
Test pitch-envelope ranges, loop crossfades and gate/one-shot stop paths with both inputs.
Effect tests include response, bypass, chain replacement and old-state retirement outside the audio callback.
Each new effect has a WAV with automatic level, timing and click checks.
For fx-core, check the makeup curve at 0 %, 50 % and 100 % against the ±1.5 dB RMS limit.
Test both directions through the DJ filter centre, its moving/rest resonance and both lo-fi endpoints.
Test cancellation, disk failure and occupied destinations without damage to source work.
Every sound render checks finite values, clipping, expected silence and timing within one sample of its reference schedule.

Planned renders: the existing plan names `renders/102-sample-tempo.wav` and `renders/105-resample-in-tempo.wav`,
plus `renders/113-fx-core.wav`, `renders/114-sample-ops.wav` and `renders/115-export.wav`.
The pitch-envelope and loop proposals also name their own renders.
These are future artifacts, not files created by this planning task.
The owner completes the full loop from each input, compares resamples and opens the exported WAV.

## 4. Everything else is 1.x

These ideas wait until after 1.0. Do not start their changes before then:

- Launcher, scenes, DJ mode and looper.
- Library tags, automatic categories and similar sounds.
- Keygroups, chromatic mode (106), chord mode, arpeggiator, tuner and project key.
- Modulation: LFOs (108), pressure, macros, snapshots and long automation.
- More lockable parameters from 104, groove templates, variations, pattern chains and recording takes.
- **Phrase variation, instead of mutations:** one variation knob sets the chance of adding a 1/16 retrigger after a hit and swapping a slice.
  At each phrase, compute a new variant from the original pattern. Phrase length is 1, 2 or 4 bars, with 2 as the default.
  Keep the first half of the first bar as written, to anchor the groove.
  - **Warp:** one knob sets the chance that a hit plays stretched or at half speed, one octave down.
  - **Phrase-end fill:** choose a random roll from the matrix, starting 8, 4 or 2 steps before the end.
    Do not choose a roll that does not fit. A 1/32 roll needs 2 steps or fewer.
  - **Freeze:** retain the current variant instead of a new one each phrase.
  - **Back to straight:** one action resets variation and warp to zero.
  - **Repeatability:** keep a seed per pattern so a variant can play again.
    The written pattern never changes. Compute variation at playback.
- Slice follow and playhead mode.
- **Real-time old-sampler stretch:** per-hit stretch in the audio thread, separate from `stretch-offline`.
  Read overlapping grains at the slice's pitch while the source timeline moves slower, at 2× or 4× stretch.
  Grain length is about 38 ms and the crossfade is 10 ms. Both are settings.
  The metallic early-sampler sound is intentional. It can be a step lock or a roll-matrix cell.
  Keep callback work allocation-free and within the budget. The 1.0 matrix uses its half-speed fallback until this exists.
- **Tuned comb feedback:** a short feedback delay with a note-controlled length, C to B, and an octave setting.
  Feedback ranges from 0–90 %. Match its level with a makeup curve and the fx-core RMS check.
- Break to pattern and tempo-following time stretch. Extreme offline stretch beyond the 0.4b scope is later work.
- Granular freeze and other granular or spectral effects, sidechain and stems.
- Buses, send chains on buses, layers per pad, ring modulator, comb and formant filters.
- Stutter on individual pad chains.
- **MIDI clock in and out:** follow Start from step 1, Continue from the stopped position, and Stop.
  One second without incoming clock also stops playback. Show the measured tempo, an `EXT` badge and `EXT` in the transport segment.
  Tempo controls are inactive while following external clock.
  With the internal clock, send Start, 24 clock pulses per quarter note and Stop to the chosen MIDI outputs.
  Put tempo halve/double actions next to tap tempo.
- Ableton Link.
- Pad lights, kits, presets and sound variation per hit.
- Recording through input effects, input noise gate and threshold auto-start.
- Plugins (LV2 / CLAP). Make a plugin decision before writing many separate effects.
- Fills, half-time, velocity ramps outside ratchets and comfort work outside the reduced 93a scope.
- AUR / Nix packages.

The detailed plans can keep these ideas and their existing numbers.
This release plan overrides their earlier order and scope. It preserves their designs.

## 5. Rules until 1.0

- Freeze the release scope. A new idea goes to [BACKLOG.md](../BACKLOG.md) as `1.x`.
  It does not start before 1.0 unless the owner moves it into 1.0.
- Each 1.0 proposal names the core-loop part or release criterion that it serves.
  It also gives exact keyboard, controller and listening checks.
- Debts block milestones. Do not close a milestone with open owner checks for its changes.
- Start [V1-FRICTION.md](../V1-FRICTION.md) now, with sessions on the current program.
  Review it at each milestone end. Only an owner decision can add a core friction fix to the release scope.
- Do not grow `crates/app/src/main.rs`. Put new code in modules.
- Keep saves, migrations and error paths in tests. A crash-free happy path is not enough.
